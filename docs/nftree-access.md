# NFTree access · v0.17

The canonical game requires a Sui Mainnet wallet and a server-verified personal-message signature. A five-minute, origin-bound random challenge is stored server-side and consumed once using an atomic conditional write. Invalid signatures, expired challenges, parallel replay attempts, non-holders and upstream failures fail closed. Signature verification uses the pinned Mysten SDK; it never submits a transaction. NFT identity is the original `0xf6c6d439ea0da2f3e9ba79e4992a7a4c113215fbf54c442ac9020c315f953705::collection::NFT` type already used by TREE Arcade. Ownership queries use Sui GraphQL, not deprecated JSON-RPC.

The ownership scan covers direct NFTrees and items in Kiosks controlled by the signing wallet's KioskOwnerCap. It checks the NFT type, Kiosk object owner and complete paginated responses; unavailable data is not counted as an empty wallet. The highest explicit on-chain rarity grants cosmetic tiers; unknown rarity defaults to Common. No ownership or rarity selector can grant entry.

An opaque 15-minute HttpOnly/Secure/SameSite=Strict cookie is issued after verification. Only a hash is stored. Authentication objects use a strongly consistent deploy-scoped Netlify Blobs store, isolated from other games and deployments. No balances, paid entitlements or game progress are stored there. Expiration is enforced on every access; Blob objects have no automatic physical TTL. Expired records may remain until the deployment store is removed; production retention cleanup is a follow-up operational task.

Game source modules are bundled privately into canopy-access. The six old public `/play/canopy-defense/src/*.js` files are removed from the new deploy; the route now requires a valid session. Game source GETs older than 30 seconds since login recheck ownership. The browser rechecks ownership every 30 seconds while visible and on return to the tab, and pauses/locks on disconnect, account change, expiry, ownership loss or an unverifiable status. Public HTML, art, wallet connector, informational preview and video remain accessible. This controls current hosted distribution and normal gameplay; previously downloaded client code cannot be recalled or protected as DRM. It must not authorize financial rewards or paid upgrades.

Progress is scoped by wallet address in localStorage. The first verified wallet in the browser can migrate the old preview save once, retaining the old save as backup; saved access/rarity never grants authority. Changing wallets reloads the app into the matching wallet's progress. Real TREE purchases are still disabled and simulated prices/balances are labeled. No persistent account/progression backend is introduced.

The wallet connector uses pinned @mysten/dapp-kit-core with Mainnet-only configuration and supports detected compatible wallets plus Slush's supported web connection. Mobile Safari/wallet-app round trips require testing on a real device. Existing game rules, prices and all other games' wallet integrations are unchanged.

Validation includes real cryptographic signatures in local tests; wrong signer/domain, replay/races, expiry, ownership loss, logout, fake cookies, non-holder, incomplete RPC/Kiosk data, protected-source access and unavailable verification are covered. Live negative access checks and browser wallet-picker checks are required before launch. A real NFTree-holder sign-in must be completed by the holder; synthetic test keys never qualify as holders. Full iPhone and signed holder gameplay verification must not be claimed based only on these tests.
